$ why

“Works on my machine” is not a diagnosis

  • FAIL A new teammate loses their first day to a missing runtime, the wrong Node version, or an unset DATABASE_URL — discovered one command at a time.
  • WARN CI catches environment drift only after it's already cost a push and a red build — an expensive place to learn your local setup is stale.
  • FAIL Docker, devcontainers, and version managers prevent drift going forward — none of them tell you whether today's checkout is actually ready.
$ what

A read-only readiness check

loadout reads the metadata your repository already has and reports pass, fail, or warn. It never acts on your behalf.

  • READS package.json, Cargo.toml, pyproject.toml, lockfiles, .env.example variants — metadata that's already in the repo.
  • NEVER Installs software, writes configuration files, or runs a package manager on your behalf.
  • EXCEPT --services opts into real connectivity checks. Every other code path is fully offline.

$ loadout --help

Three commands

01

check

The core command. Discovers requirements, evaluates them against this machine, reports pass / fail / warn.

02

doctor

Same checks — blockers grouped into ordered remediation steps, each with a link to the tool's install docs.

03

init

A discovery aid, not a setup command. Lists what loadout detects and the scripts you can already run. Writes nothing.

$ loadout doctor

Ordered, not overwhelming

Blockers are grouped in the order a developer would actually clear them.

install tools → install dependencies → configure env vars → check services

--open-docs opens each missing tool's install page. loadout only reports findings — the fix is always yours to run.

$ ci

Built for pull requests

  • SCOPE --changed <ref> checks only requirements whose source file changed against the PR's base branch.
  • ANNOTATE --annotate emits GitHub Actions ::error / ::warning lines, pointing at the exact file.
  • ACTION A reusable composite action — uses: JacobRoedel/loadout@main — no local Rust install required.
  • GATE Exit codes 0 / 1 / 2 — pass, blocked, or bad invocation. A natural CI gate, nothing bespoke to parse.
$ trust

Guardrails, not promises

  • SCOPED --services is the only code path that touches the network — a 2 second TCP dial, opt-in every time.
  • SILENT Credential values and full connection strings are never printed or written to JSON output — only host and port.
  • DURABLE .loadoutignore — a small, reviewable, repository-local list of intentional exceptions. Skips are counted, never hidden.
